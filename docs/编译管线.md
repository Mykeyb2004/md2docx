# macOS 编译管线

本管线用于在 Apple Silicon Mac 上将项目编译为可直接运行的 `Md2docx.app`。

## 进入项目目录

```bash
cd /Users/zhangqijin/PycharmProjects/md2docx
```

## 首次编译或完整重建

```bash
uv run --group build python scripts/build_nuitka.py --entry gui --mode app --clean
```

该命令会依次执行：

1. 检查 macOS、arm64、Python、Nuitka 和系统工具。
2. 运行项目测试。
3. 使用 Nuitka 编译 standalone app bundle。
4. 暂存并检查模板、Tcl/Tk 和可执行文件架构。
5. 执行本地 ad-hoc 签名并验证签名。
6. 验证成功后发布到 `dist/macos`。

## 更新应用图标

正常重复编译不需要重新生成图标；仓库已经包含 `assets/macos/AppIcon.icns`。只有修改 `AppIcon.svg` 并重新导出 `AppIcon.png` 后，才运行：

```bash
bash scripts/build_macos_icon.sh
```

图标生成脚本会用 macOS 自带的 `sips` 和 `iconutil` 创建完整尺寸集合。生成成功后，再使用下面的普通 app 命令编译：

```bash
uv run --group build python scripts/build_nuitka.py --entry gui --mode app
```

如果 `AppIcon.icns` 缺失或为空，app 管线会在 Nuitka 启动前失败并提示先生成图标。

## 日常重复编译

保留已有中间产物，可缩短后续编译时间：

```bash
uv run --group build python scripts/build_nuitka.py --entry gui --mode app
```

## 编译成功后自动启动

```bash
uv run --group build python scripts/build_nuitka.py --entry gui --mode app --clean --launch
```

## 快速迭代时跳过测试

```bash
uv run --group build python scripts/build_nuitka.py --entry gui --mode app --skip-tests
```

`--skip-tests` 只适合本地临时迭代；准备交付时应运行包含测试的完整命令。

## 启动已经生成的应用

```bash
open /Users/zhangqijin/PycharmProjects/md2docx/dist/macos/Md2docx.app
```

也可以在 Finder 中直接双击：

```text
dist/macos/Md2docx.app
```

## 输出文件

```text
dist/macos/
├── Md2docx.app
└── default.yaml
```

- 应用：`dist/macos/Md2docx.app`
- 可编辑配置示例：`dist/macos/default.yaml`
- 完整构建日志：`build/logs/macos-app-build.log`
- Nuitka 中间产物：`build/nuitka`

候选应用首先生成在 `dist/macos.staging`。只有测试、编译、签名和验证全部成功后，管线才会替换 `dist/macos`；失败时会保留上一次成功的应用。

## 环境说明

- 仅支持 macOS Apple Silicon（arm64）本机构建。
- 使用 `uv` 管理环境和依赖。
- `.python-version` 固定为 Python 3.11.9。
- 不要改用 uv Python 3.12.11 构建：该版本的动态 `_tkinter.so` 可能导致 Nuitka 在执行 `install_name_tool` 时因 Mach-O 头空间不足而失败。
- 当前使用 ad-hoc 签名，适合本机运行；Developer ID 签名、公证、DMG 和 universal binary 不在此管线范围内。

## 构建失败时

先查看日志：

```bash
less build/logs/macos-app-build.log
```

然后执行一次完整清理构建：

```bash
uv run --group build python scripts/build_nuitka.py --entry gui --mode app --clean
```

如果错误发生在测试阶段，应先修复失败测试；如果发生在编译阶段，日志中会保留完整的 Nuitka 输出。
