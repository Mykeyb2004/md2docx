# 输出文件覆盖确认设计

## 背景

CLI 已在输出文件存在时拒绝转换，并要求用户显式传入 `--overwrite`。GUI 当前会直接启动转换线程，因此当输出路径已经存在时可能静默覆盖文件。

## 目标

- GUI 在覆盖已有输出文件前获得用户明确确认。
- 默认行为为取消覆盖。
- 不改变 CLI 的 `--overwrite` 行为。
- 不改变 `Converter` 的公共接口。

## 交互设计

`Md2docxGUI.convert_file` 完成输入路径、输出路径和输入文件存在性校验后，检查输出路径是否已经存在。

- 输出文件不存在：直接启动现有转换线程。
- 输出文件存在：显示“确认覆盖”对话框，包含目标文件路径，默认按钮为“否”。
- 用户选择“否”或关闭对话框：立即返回，不启动转换线程。
- 用户选择“是”：继续启动现有转换线程。

确认框使用现有的 `dialog_parent()` 作为父窗口，保持窗口层级和多屏显示行为一致。

## 实现范围

修改范围仅包括：

- `md2docx/gui.py` 中的 `Md2docxGUI.convert_file`。
- `tests/test_gui.py` 中覆盖确认相关测试。

当前工作区内 `_do_conversion` 的进度条修改及其测试保持不变。

## 测试

- 已有输出文件且用户取消时，不创建或启动转换线程。
- 已有输出文件且用户确认时，按原流程创建并启动转换线程。
- 现有 GUI 测试继续通过。
- CLI 覆盖保护测试继续通过，证明其行为未发生变化。
